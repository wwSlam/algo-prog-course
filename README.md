# algo-prog-course
1. В Python ошибка вылезет только когда программа дойдёт до этой строки. А в C# компилятор сначала читает весь код целиком, и если есть синтаксическая ошибка — программа вообще не соберётся, даже если эта строка никогда бы не выполнилась.
2. Два шага: сначала build (компилирует .cs файлы), потом запускает получившуюся программу.
3. bin/ — скомпилированная программа, obj/ — промежуточные файлы сборки. Это не исходники, а результат работы компилятора на конкретном компе. Они спокойно пересоздаются командой dotnet run, поэтому в Git их не заливаем — для этого есть .gitignore.
4. commit — сохраняет снимок изменений локально у меня на компе. push — отправляет этот снимок на GitHub.
5. склеивает строки, но когда переменных много — код становится нечитаемым. $"..." то же самое, но нагляднее. Используем интерполяцию — она понятнее.
6. Дробная часть просто отбрасывается (не округляется!). Например 25 / 4 = 6, а не 6.25. Чтобы получить точный результат, надо одно из чисел превратить в double через (double) — это явное приведение типов.
7. const задаётся один раз и потом не меняется — компилятор не даст переприсвоить. Обычная переменная меняется сколько угодно. Пример: const double VatRate = 0.20; — НДС зафиксирован законом, так и должно быть.
8. Это когда можно писать код сразу в Program.cs без class Program { static void Main() { ... } } — компилятор сам всё достраивает. Появилось с C# 9. Мы так пишем весь семестр, потому что короче.
